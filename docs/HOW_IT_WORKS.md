# How it works

This document explains the two halves of the repo: the **agent** (`money-agent/`) and the **video generator** (`video/`),
then walks you through changing the video yourself.

---

## 1. The agent in one picture

```
 data/transactions.csv
        │
        ▼
┌───────────────────┐  ┌─────────────────────┐  ┌──────────────────┐  ┌──────────────────┐  ┌───────────────────┐  ┌────────────────┐
│ load_transactions │→ │ categorise_expenses │→ │ analyse_spending │→ │ detect_anomalies │→ │ generate_insights │→ │ prepare_report │
└───────────────────┘  └─────────────────────┘  └──────────────────┘  └──────────────────┘  └───────────────────┘  └────────────────┘
  ₹/commas, 3 date        rules → LLM (optional,     totals, categories,    3× usual · new          sentences that          output/report.json
  formats, drop bad       validated) → "other";      month-over-month,      merchant > ₹2,500 ·     quote their numbers     → main.py / app.py
  rows (and say which)    your overrides win         recurring payments     duplicate in 2 days
```

* **`tools.py` holds the logic, `agent.py` holds the order.** Each node in `agent.py` is a three-line wrapper: call one tool, log what happened,
  return the part of the state it changed. This keeps the tools testable on their own (`python tools.py data/transactions.csv`).
* **LangGraph** (`StateGraph(State)`) passes a typed dict (`State`) from node to node. The graph is a straight line today, which makes it easy
  to add a branch later (for example "if there are no debits, skip to the report").
* **The human stays in charge.** `run(csv, overrides, dismissed)` takes your corrections and dismissed alerts as input, so they are re-applied
  on every run. `app.py` stores them in `output/state.json`. The agent never "learns" silently, and it has no tool that touches money.
* **Bad data is reported, not guessed.** Row `T018` has amount `N/A`, `T041` has the date `31/09/2026` (September has 30 days) and `T067` has no
  description. They are dropped and listed in the report.

## 2. The video generator

### 2.1 One page, one function

`video/src/index.html` is a 1920×1080 "stage" containing hand-built mock-ups of VS Code (title bar, explorer, tabs, editor, terminal panel,
status bar), a browser window, a server terminal and the overlays (scene card, time-lapse badge, cursor, click ripple, tagline).

`timeline.js` defines **`seek(t)`**: for a time `t` in seconds it sets every element to exactly how it should look at that moment.
There are no timers or CSS animations, so:

* any frame can be drawn instantly and in any order (that's how `?t=30`, `preview.py` and parallel rendering work), and
* a slow 4K screenshot can never cause a dropped frame.

`render.py` opens the page in headless Chromium, calls `seek(i / 30)` and screenshots frame `i`, for all 2,625 frames.
For 4K it uses `device_scale_factor=2`: the same layout drawn with twice as many pixels, so text stays razor-sharp.

### 2.2 Files

| File | Job |
|---|---|
| `engine.js` | Drawing helpers that know nothing about this particular video: easing, `Doc`, syntax highlighters (Python, HTML+CSS+JS), `renderEditor`, `renderTerm`. |
| `timeline.js` | The script: `DOCS` (what is typed when), `OPEN` (when tabs open), `TERM` (terminal), `PANEL`, `CARDS`, `BADGES`, `CUR` (cursor), and `seek(t)`. |
| `dashboard.js` | Runs the real dashboard inside the video's browser window. |
| `captured.js` | Generated by `capture.py`. Never edit it by hand. |
| `player.js` | `?play` mode: scales the stage to the window and calls `seek()` every animation frame. |

### 2.3 Typing code as real edits

A file in the editor is a `Doc`: a list of timed edits.

```js
{ pos: 1234, del: 87, ins: "    amount = df[\"amount\"].str.replace(...)\n...", t0: 21.0, t1: 22.5 }
```

At time `t`, every finished edit is applied in full; the edit in progress deletes its old text at `t0` and then "types" `ins` character by character
until `t1`. The caret, the scroll position (which follows the caret smoothly) and the unsaved-dot on the tab all come from that.

`tools.py` is typed in **four versions**, which `capture.py` derives from the final file:

| Version | Content | What happens when it runs |
|---|---|---|
| v1 | loader with `astype(float)` and `pd.to_datetime` | **real `ValueError`** on `'15,000'` (scene 2) |
| v2 | the fixed loader | `133 rows read, 3 dropped …` |
| v3 | + `CATEGORIES`, `RULES`, `merchant`, `categorise` … | category sources printed |
| v4 | the final file | totals, recurring, flags |

The edits between versions come from `difflib.SequenceMatcher` (line opcodes → `{pos, del, ins}`), and `timeHunks()` spreads them over the
time window given in `DOCS`, proportionally to how much text each edit types. So the video edits the file the way a person would:
it replaces the two broken lines rather than retyping the whole file.

### 2.4 capture.py: only real output

`capture.py` copies `money-agent/` to a temp folder and:

1. runs `pip install -r requirements.txt` in a throw-away venv and records it (`--skip-pip` reuses the last recording);
2. writes v1…v4 of `tools.py` and runs `python tools.py data/transactions.csv` after each;
3. runs `python main.py data/transactions.csv`;
4. starts the real `app.py`, uploads the CSV over HTTP, corrects Sri Sai Enterprises → education, dismisses the first alert,
   and keeps the three JSON reports and the Flask log;
5. replaces temp paths with `/home/dev/projects/money-agent`, so the terminal looks like a normal laptop;
6. writes everything to `video/src/captured.js` as `window.CAP = {...}`.

`timeline.js` only decides *when* things appear; *what* appears always comes from `CAP`.

If you change `money-agent/`, also run `python build-along/make_steps.py`. It rebuilds the eight build-along checkpoints,
their `EXPECTED_OUTPUT.txt` files and `build-along/README.md` from the same tools.py versions, so the guide, the checker and the video always agree.

### 2.5 The dashboard is the app's own HTML

`dashboard.js` takes `money-agent/templates/index.html` from `CAP.dashboard` and:

* puts its `<style>` and markup into a **Shadow DOM**, so its CSS can't affect the VS Code mock-up (and vice versa);
  `:root` becomes `:host`, `100vh` becomes the browser window's height, and the toast transition is removed because `seek()` animates it;
* runs its `<script>` with `new Function('document', 'setTimeout', …)`, handing it a `document` that looks inside the shadow root;
* calls the page's own `show(report, message)` with the captured reports.

Because the numbers, the donut chart, the toasts (*"Recalculated · education: ₹1,079 → ₹1,489 …"*) and the review list are drawn by the app's own code,
the video can't drift from what the app really does.

### 2.6 The cursor

`CUR` is a list of keyframes `{t, x, y}` or `{t, at: 'selector'}`. `at:` entries are resolved at render time with `Dash.point()`, which measures where
an element really is inside the dashboard. If you change the dashboard layout, the cursor still lands on the right button. `c: 1` adds a click ripple.

## 3. Tutorial: change the video (about 15 minutes)

Do this with the venv from the main README active, from the repo root.

### Step 1: change a scene title (no re-capture needed)

In `video/src/timeline.js`, find `CARDS` and change

```js
  [42.0, 5, 'Connect the agent workflow', 'LangGraph: load → categorise → analyse → detect → insights → report'],
```
to
```js
  [42.0, 5, 'Wire up the LangGraph agent', 'Six nodes, one straight line: START → … → END'],
```

Then check it:

```bash
python video/scripts/preview.py 45
```

Open `video/output/stills/t_045.0.png`: the scene card shows your text.

### Step 2: change the agent and let the video follow

The dashboard in scene 8 lists **Raju General Store** under "Check these categories" because no rule matches it.
Teach the agent: in `money-agent/tools.py`, add `"general store"` to the shopping keywords:

```python
    "shopping": ["amazon", "flipkart", "myntra", "ajio", "general store"],
```

Run the agent and the self-check:

```bash
cd money-agent
python main.py data/transactions.csv      # shopping ₹4,447 → ₹4,677, other ₹7,139 → ₹6,909
python check_numbers.py                   # the last line is now ✗ (other is ₹230 lower) — expected, you changed the agent
cd ..
python video/scripts/capture.py --skip-pip
python video/scripts/preview.py 70
```

In `t_070.0.png` the "Check these categories" card has one row fewer and the shopping slice is bigger. Look at the Gadgetworld alert too:
it now says *15.9x your usual other spend* instead of *17.3x*, because the "usual other spend" (the median) changed. One keyword moved
a number somewhere else on the page, which is why every alert shows the rule and the numbers behind it. In scene 3 the editor now types
your new keyword, because the video types whatever is in `tools.py`.

### Step 3: slow down a typing section

In `DOCS`, `agent.py` is typed between 42.7 s and 48.8 s. Make it 42.7 → 49.6 and check that `OPEN` (`['main.py', 50.0]`) still comes after it.
Preview at 49 s, then render only that part to check the motion:

```bash
python video/scripts/render.py --start 42 --end 51
```

### Step 4: render the whole thing

```bash
python video/scripts/render.py                  # 1080p
python video/scripts/render.py --quality 4k     # 4K
```

## 4. Exercises

1. **New anomaly rule.** In `detect_anomalies`, flag any single spend above 30% of the month's total. Re-capture: how many alerts does scene 8 show now?
2. **A branch in the graph.** In `agent.py`, use `graph.add_conditional_edges` to skip `detect_anomalies` when there are fewer than 10 debits.
3. **Budget insight.** Add a `BUDGETS = {"food": 10000}` dict and an insight when a category goes over budget. Show it in the dashboard.
4. **A new terminal command.** In `TERM`, after `python main.py …`, add `{ k: 'cmd', prompt: 'p2', text: 'ls output', t0: 54.5, t1: 54.9 }` and an `out`
   entry with the text `report.json`. (The prompt after a command is inserted automatically.)
5. **A new scene.** Add a 5-second scene before the finale that opens `output/report.json` in the editor: a new entry in `DOCS` and `OPEN`, a `CARDS` row,
   and move the later times (and `DUR`) back 5 seconds.
